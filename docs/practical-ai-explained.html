Practical AI, explained

Ten tools, eleven skills and one way of building them. What is here, how it was made, and how to use it today.

What this is

A toolkit of practical AI tools for small businesses, kept in one repository. Each tool is something a person can set up and use, mostly without writing code.

Think of it as a workshop wall.Every tool hangs in its place with a tag: what it does, how to use it, and how well it has been tested. You take down the one you need.

How every tool is laid out

The same folders in the same order, so once you know one tool you know them all.

  1. DemoA finished example to open. Nothing to set up.
  2. BeginnerThe smallest version you can run: usually one sentence or one page of instructions pasted into a chat Project.
  3. AdvancedThe common size. Your own templates, colours and rules, saved once and reused.
  4. ExpertA skill does the job and checks its own work. A person still approves anything that goes out.
  5. Commercial gradeAn explanation of what a business-critical version adds. Never a project.

Each tool also has a guide for people, a guide for agents, and notes on what already exists.

How each one is built

The same loop every time. Building is the short part.

  1. Scope and researchSay what it is for. Then find what assistants, browsers and free tools already do, with dated sources. Reuse before building.
  2. The simplest version that worksA demo and a beginner level. Nothing more until those exist.
  3. Score itSeven questions, from "can a non-coder use it" to "has anyone else tried it". Written down, with the reasons.
  4. Fix the weakest thingNot the most interesting thing. Then score again.
  5. Stop when evidence is the weakest itemAt that point more building does not help. Someone else has to use it.

Every tool here has now reached that last step.

The centrepiece: artifact studio

Tell the assistant three things it would otherwise guess: what kind of page this is, how it should speak and what it should look like.

Think of it as ordering at a counter.You do not explain how to cook. You name the dish, say how you like it, and it arrives on a plate. The studio is the menu.
RecipeThe dish. What kind of page: a report, a proposal, an explainer or a landing page.
VoiceHow you like it. Who is speaking, and what they say first.
LookThe plate. Colours, type and layout, from your brand or from a photo.

How the studio makes a page

Four stages, always in this order. Each one narrows the next. Scroll and the diagram keeps your place.

  1. Stage 1. Three choices

    Choose the recipe, the voice and the look

    Start with the job of the page: who reads it and what they should do next. That picks the recipe. The recipe suggests a voice. The voice suggests a look.

    • 4 recipes, 7 voices, 9 looks
    • Or colours taken from a photo you attach
  2. Stage 2. Words before pixels

    Write the outline and list the gaps

    Your content is mapped onto the recipe's sections, in the order the voice sets. Anything missing is marked on the page as a gap. Nothing is invented to fill it.

    • No made-up numbers, names or quotes
    • Every assumption is written down
  3. Stage 3. One file

    Build it from parts that carry content

    Each section gets a part only if it needs one: big numbers for results, a timeline for a schedule, a table for a choice. The result is one file that opens anywhere.

    • 24 parts to choose from
    • Three moving parts at most
    • Designed for a phone first
  4. Stage 4. Before anyone sees it

    Check it, then look once

    A short checklist, then one read on a phone. The page comes back with a note: what was chosen, what was assumed, what is missing and what you should verify.

    • A person decides whether it is shared

What the studio is made of

Four shelves. Every item is a working example with the sentence that asks for it.

4RecipesOne-page report, proposal, scrolling explainer, landing page
7VoicesKeynote, storyteller, teacher, pitch, practical instructor, analyst, executive brief
9LooksCards such as paper memo and field guide, your own spec, or a photo's colours
24Parts12 that need no photo and 12 built from one photograph

The seven voices are the part most people have not seen before. Each voice page in the studio makes the same case with the same facts, and each comes out as a different page, because a voice changes the order of what is said and not only the wording.

Stop at the level that is enough. Each level has its own page, and a fourth page holds every example.

For agents

The same menu, as a skill. An agent loads it, follows nine steps, and returns the page with a note in this form.

Chose: proposal, practical instructor, brand spec.
Assumed: the start date is the first Monday after acceptance.
Missing: [needs: payment terms]
Check before sharing: the three option prices against the estimate.

Three rules never bend: no invented facts, a voice is a style and never an impersonation, and nothing is posted or published without a person saying so.

How the studio was built

The loop above, run on the first tool. The same loop was then run on the rest of the list.

  1. Research firstWhat browsers, free libraries and existing skills already do. Dated sources, saved as a landscape review.
  2. The simplest thing that worksA gallery of 12 components from one lake photo. Self-scored at 61 out of 100: a good demo, not yet a tool.
  3. The gap, namedIt stopped at components. Nothing was a page a business needs, and nothing made it repeatable.
  4. Rebuilt as a studioRecipes, voices, plain components, a sentence builder, all levels, guides for people and agents, and a skill.
  5. CheckedThree screen widths, an automated accessibility scan, link and arithmetic checks. Self-scored at 77.
  6. Then the rest of the listSkills, agent guides and upper levels for four existing tools. Demo pages built with the studio's own skeleton. Five more tools started from their plans.

What is proven and what is not

CheckedAll 46 tabs of the four studio pages and the nine other demo pages render in Chrome at phone width with no errors and no sideways scrolling. An automated accessibility scan found no violations after fixes. The example arithmetic adds up.
Not yet testedThe sentences have not been run in fresh chats and scored. The skill has not been run by a second agent. One outside look so far, by the repository owner on a phone. It found the examples hard to reach. That is fixed and the fix is not yet confirmed. No Safari or Firefox.
Thin researchTools 8 and 9 were started from notes, with no checked sources. Their plans say so. No publishing route has been walked end to end.
A guessThe practical instructor voice is a best guess at one person's teaching style and has not been corrected by him.
