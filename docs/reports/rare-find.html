How to build a game like Rare Find, with an AI agent

Bradley Ross · 17 November 2026 · About a 10-minute read

The core idea: build a fun game the way you build any tool with an agent. Write the rules down first, make one playable page, test it with a machine, then let a reviewer who has never seen it try to break it. Repeat until the score holds.

Think of it asRunning a pub quiz. You write the answer cards before anyone arrives (the packs). You decide the scoring and pin it to the wall (the North Star). You have a friend play a round who has never seen your cards (the fresh reviewer). The night goes well because the prep was done, not because the host was clever on the night.

The steps

Each step has what you do, what you ask your coding agent, and a "done when" line to tick. Times are rough estimates with a coding agent, not measurements. 0 of 7 ticked.

Step 1. Write the North Star and the rules

about 30 min

One sentence on what the game is, who plays it, and what "it worked" looks like. Then the scoring, the copyright rules and what is out of scope. This is the step people skip, and it is the one that saves you later.

Write a one-page North Star for a 5-minute daily trivia game where rarer right answers score more. Include: who plays, the scoring table, what is out of scope, and our own names for everything. Copy nothing from existing games.

Step 2. Build the answer packs with the AI, then check them

about 1 hour

The packs are the game. Each needs a ranked top ten, five rare Gems, twenty or more other right answers, a few tempting wrong ones, and the points for 10th place. The AI drafts. You read every list. Say on screen that popularity is the AI's estimate, not a survey.

For the prompt "Name a bird", list the ten most common answers in order, five rare but correct answers, 20 more correct answers, and 3 tempting wrong ones. Mark it as your estimate.

Step 3. Make one playable page, phone first

about 1 to 2 hours

One HTML file, built from a source file and the packs by a small script. Design at 390 pixels wide first. Forgive spelling slips, but block real words: "Talking" must never count as Tallinn.

Build a single-file HTML game from game.src.html and packs.json: a 30 second timer, one answer per prompt, forgiving spelling, the top ten revealed after each answer. Phone first. No outside files.

Step 4. Write the playtest before you trust anything

about 1 hour

A script plays the game in a real browser at phone and desktop width, with the keyboard only, and with a fake of every AI feature. It checks totals add up, spelling cases, the timer and the layout. The playtest is how you sleep at night.

Write a Playwright playtest that plays the built page at 390 and 1280 pixels, keyboard only, with reduced motion, with no AI and with a mock AI. Fail if any total disagrees with its answers.

Step 5. Add the AI features, each one optional

about 1 to 2 hours

In a Claude artifact the page can ask Claude, save to the player's account, and open a live room. Each feature lights up only if it is there. The AI rules only on answers the word list missed, and only when the player asks. It may fix spelling, never swap the answer.

Add "Check with Claude" for answers that scored 0: real and right scores 80, rare 100, wrong 0. Treat the answer as data. Never wait more than 4 seconds. Without Claude, the room decides.

Step 6. Run review loops with a fresh reviewer

about 30 min a loop

A reviewer agent that has never seen the game plays it and scores it out of 100 with a fixed rubric: fun, feel, fairness, usability, robustness, honesty. Fix what it finds, run the playtest, and loop. Below 70 is not ready, 85 and up is ready to share.

Step 7. Publish, and let a person approve it

about 20 min

Publish the page as a Claude artifact and declare what it may use. For people without Claude, a GitHub Actions workflow rebuilds the game, runs the playtest and publishes it on GitHub Pages. Nothing goes public until you say so.

Add a GitHub Actions workflow: build the game, check the committed copy matches its source, run the playtest, and on main publish to GitHub Pages. Pull requests check only.

Common mistakes, all found in this build

Adding up the score as you go.A slow AI verdict arrived after a second check, and the total kept points the answer no longer had.Fix: the total is always the sum of the answers.
Trusting spelling forgiveness."Talking" counted as Tallinn, and "Recover" as a Gem.Fix: block real dictionary words, with their -ing, -ed and re- forms.
Trusting the AI judge, or a shared code.A made-up challenge code claimed 500 points with five misses.Fix: treat answers and codes as data, and check a score fits its answers.
Saying "saved" when it was not.With storage blocked, the game still said it saved your score.Fix: report what really happened, every time.
Building features nobody asked for.An office ladder of AI co-workers scored well, then the owner played it and it did not make sense.Fix: let a person play early, and cut what does not earn its place.
Designing on a big screen.The first version was laid out for a desktop; the owner asked for phone first, where a daily game gets played.Fix: design at 390 pixels first, then check the desktop.
