# The process on one page

Nine steps from an idea to a tool someone else can try. Each step ends at a gate: a plain
question you must be able to answer before you go on.

**Think of it as** building a deck in the garden. Decide what it is for. Check whether a kit
already exists. Price the wood. Pick the spot. Draw it. Have someone check the drawing. Build the
smallest platform you can stand on. Extend it only once you are using it.

| # | Step | You write down | The gate |
| --- | --- | --- | --- |
| 1 | **Scope** | One user, one job, what is out, and the one thing that will make people stop and look | Can you say the job in one sentence? |
| 2 | **Reuse check** | What already does this: built in, free, common practice | After what already exists, is there still something to build? If not, stop and write a guide to that thing |
| 3 | **Outside help** | Paid services for whatever is left. List them. Do not choose yet | Do you know what you would build and what you would buy? |
| 4 | **Cost** | Every dependency of the first version, with its price and its limit | Does the beginner version cost nothing, or a known amount? |
| 5 | **Simplest design** | Which assistant, where files live, what stays manual. The folder layout, fixed now | Could a beginner draw it? |
| 6 | **Plan and front door** | The steps a person follows, the first screen they see, one worked example for each kind of request it handles | Is the beginner version fully described? |
| 7 | **Review** | Someone who is not the author reads the plan | Can they explain it back to you? |
| 8 | **Build the smallest version and test it** | The beginner version. Then a test by a fresh AI session that has only your instructions | Did the fresh session finish the job, and what did it trip on? |
| 9 | **Grow one step at a time** | One addition, one change request. What you learned | Is the level below in use before you build the next? |

## Who does what

| Step | The AI does | You do |
| --- | --- | --- |
| 1 to 4 | Asks the questions, searches for what exists, lists costs | Answer honestly. Say no to anything outside the one job |
| 5 to 6 | Drafts the design, the plan and the first screen | Cut it down. Fix the layout and do not change it later |
| 7 | Plays the reviewer if no person is free, in a fresh session | Find a real person if you can |
| 8 | Builds, and runs the fresh-session test | Read what the test tripped on. Decide what to fix |
| 9 | Makes each addition | Approve each one. Use the tool yourself |

## Five rules that save the most time

They come from the first tool built this way, which changed its folder layout four times.

1. **Name the wow first.** Decide the one thing that makes people stop, and build it first.
2. **Fix the layout before you build.** Moving files later breaks links and wastes a day.
3. **Test in a fresh session early.** One fresh run found three times as many faults as the author.
4. **Say what a result really is.** A page built by hand is a reference. A page a chat made is an example.
5. **One addition, one change request.** Small changes get reviewed. Big ones get waved through.
