Agentic Process · back to basics

A person, or an agent working alone, can take an idea or a spec to a tool that someone else can use, without rebuilding it three times on the way.

That is the North Star. Everything in the project, the nine steps, the coach, the checks and the course, exists to move someone toward it.

The purpose

AI made building cheap. Deciding what to build is now the expensive part.

Think of it as a building site with an inspector. You agree the drawing before you pour concrete, and nothing moves to the next stage until the current one is signed off. The inspector does not slow the build down. The inspector stops you pouring concrete in the wrong place.

An AI will build whatever you ask, quickly and with confidence. So the costly mistakes now happen before the first line is written. Agentic Process puts cheap checks in front of the build so that three mistakes stop happening:

The wrong jobAsked for five things, you get a tool that does none of them well. Step 1 cuts it to one user and one job.
It already existedA built-in feature or a free tool already did it. Step 2 checks first, and stopping counts as a win.
Only you can use itIt works in your chat, with everything you said earlier. Step 8 hands it to a stranger before anyone relies on it.

The value proposition

Build the right small tool once, and prove it works with a stranger before you rely on it.

For anyone who uses AI at work: nine short steps that stop you building the wrong thing, check what already exists, and test the result with a fresh chat that knows nothing, in the chatbot you already have, for free.

Beginner

Someone with a job they repeat, using any chatbot

Without it

Trial and error in a chat until something works on the day; next week you start again

With it

A one-page plan, a prompt they can reuse, and a test they can rerun whenever they change it

Advanced

A builder working with a coding agent

Without it

The agent builds fast and the shape is found by rebuilding; folders move and links break

With it

A project folder with its own checks, a front page written before the tool, and a stranger's test before polish

Expert

A team whose agents work unattended

Without it

The author reviews their own work and passes it, because they know what they meant

With it

Fresh-session tests, gates a script can run, and a hand-back a person reads before anything ships

We expect the larger gain to be quality, not speed. Every time in the project is an estimate, because nobody has been timed yet.

How you know it is working

The test of the North Star is a stranger finishing the job.

For your tool

A fresh chat, with only your instructions and one real input, finishes the job, and its list of where it had to guess has no blocking points left.

For this project

Three numbers, from a two-minute form anyone fills in after building a tool: how many tools passed a fresh-chat test, the minutes from first paste to a one-page plan (aim: under 30), and how many tools someone other than their builder used.

Where it fits

It starts earlier than spec-driven toolkits, and it works outside a code editor.

ApproachWhat it does wellWhere it stops

Spec-driven toolkits such as GitHub Spec Kit, Kiro and BMADTurn a specification into plans, tasks and code, inside a developer's toolsStart once you have decided to build, and are made for developers

Spec-driven toolkits, checked on 16 November 2026: GitHub Spec Kit runs specify, plan, tasks and implement with a coding agent; Kiro writes requirements, a design and tasks; the BMAD Method uses role-based agents from analyst to developer. They suit large builds by developers. Agentic Process is designed to sit in front of them; that has not been tried yet.

What it is not

Four things this project does not claim.

  • It is not a way to build large software. It is for small tools: one user, one job.
  • It does not replace your judgement. A person approves anything that is sent, posted, paid or published.
  • It does not promise time saved. The times are estimates until learners are timed.
  • It is not proven outside Claude yet. It is written for any chatbot.

The nine steps

Four stages, a gate after every step.

  1. Scope Can you say the job in one sentence?
  2. Reuse check After what already exists, is there still something to build? If not, stop and write a guide to that thing.
  3. Outside help Do you know what you would build and what you would buy?
  4. Cost Does the first version cost nothing, or an amount you accept?
  5. Simplest design Could a beginner draw it?
  6. Plan and front door Is the beginner version fully described?
  7. Review Can someone else explain it back to you?
  8. Build and test Did a fresh session finish the job, and have you read what it tripped on?
  9. Grow Is the level below in use before you build the next?

The quickest way to run them: paste this into any chatbot and change the last line to your job.
