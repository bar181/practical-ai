# Friction note (out of role)

The guide was followable, but five places made me guess.

1. **Recipe fit.** "A page, with a voice named and no recipe" sends me to the recipe that lists keynote. That is the scrolling explainer, which is meant for a process or idea. This content is a monthly update with a decision, which is a one-page report, but that recipe lists only analyst and executive brief. I followed the rule. The explainer's "image that stays on screen" and "one block per stage" did not fit, so I let the voice's order win and left them out. The rule should let a named voice borrow the recipe that fits the content.
2. **The keynote's "catch" beat.** The notes give no reason the van matters (cost, crews sharing one van, lost jobs). Writing one would be inventing, so I left the beat out and listed it under Missing. The page reads as good news, then a date, with no stakes between them.
3. **Count-up versus "tie movement to scrolling".** If a count-up is tied to scroll position, the page can come to rest showing a wrong, half-counted figure. So I made the count start when the number comes into view and always end on the real figure. The guide gives no CSS-only form for a count-up; with scripts off the final numbers simply show. The guide should say which parts are scroll-tied and which are timed.
4. **Self-drawing line art** is listed under "With a photo", but the user wants it as the no-photo fallback. The guide does not say what to draw. I chose a van because the decision is about a van, and labelled it as an illustration.
5. **Small wording clashes.** "Source: your notes" is right for the person who wrote the notes, but this page is read by the business partner, so it reads oddly. The twelve-words-a-screen limit is tight for a chart that needs a full-sentence heading, a unit, a source and its working. I fitted it at eleven words, with the sum written as numbers. The `[needs: owner]` example for a next step left me unsure whether a keynote next step needs an owner. I did not mark one.

I could not render the page. The checks were done by reading the code: tag balance, script syntax, bar heights (71,500 x 180 / 84,200 = 152.85) and the $12,700 difference.
